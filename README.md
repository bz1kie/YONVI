# YORVI — маркетплейс внутри MAX

YORVI («Нашёл — твоё») — маркетплейс объявлений с единой карточкой товара, несколькими кругами сообществ и независимой модерацией. Фирменный маскот — Йори-енот.

## Состояние: 2.0 alpha (10 ноября 2026)

Исходники интерфейса 1.4 перенесены на **React + TypeScript + Vite**, сохранены экраны, фотографические демо-ресурсы и персонаж Йори. Fastify API умеет отдавать активные объявления, **одобренные хотя бы в одном круге**. Клиент запрашивает серверный каталог; если база недоступна или пуста, показывает явно маркированную локальную демоверсию. Никаких реальных интеграций MAX пока нет.

**Важно:** создание и модерация товаров в интерфейсе пока сохраняются в localStorage — это не серверные операции. В API есть экспериментальные write-маршруты, но демо-аутентификация отключена по умолчанию. Запрещено выставлять её в интернет; сначала требуется серверная проверка MAX initData и права доступа.

## Стек

React 19 + TypeScript + Vite · Fastify 5 · PostgreSQL 17 · npm workspaces · Docker Compose · Node 22.

## Локальный запуск

```bash
npm install
docker compose up -d db
# отдельная команда заполняет тестовую базу (один раз или повторно)
docker compose exec -T db psql -U yorvi -d yorvi < packages/database/seeds/001_demo.sql
npm run dev:api
# в другом терминале
npm run dev:web
```

Frontend: http://localhost:5173 · API: http://localhost:3001/health · GET /api/listings.

В каталоге API должны появиться две тестовые карточки, а «Проданный велосипед» появляться не должен.

Тесты и сборка:

```bash
npm test
npm run build
```

CI на GitHub запускает установку, 6 доменных тестов и сборку обоих приложений.

## Что ещё не готово

Авторизация MAX и серверная RBAC; запись объявлений из интерфейса в PostgreSQL; сохранение избранного и фотографий на сервере; доставка уведомлений; платежи; интеграционные PostgreSQL и e2e-тесты. Не использовать alpha-сервер как публичную торговую платформу.
