# Фото объявлений YORI 2.0 — S3-совместимое хранилище

## Реализовано
- В личном кабинете продавец выбирает **созданное объявление**, файл JPEG/PNG/WebP до 5 МБ и загружает его.
- `POST /api/media/uploads` проверяет права владельца, допустимый MIME, размер и лимит **10 файлов** на объявление. Создаёт строку `pending` и подписывает прямую загрузку S3 PUT на **300 секунд**.
- Браузер передаёт бинарный файл непосредственно в S3 по подписанной ссылке; токены доступа к бакету в браузер **не передаются**.
- `POST /api/media/:id/confirm` проверяет объект по HEAD (размер и MIME) и первые байты (JPEG/PNG/WebP). Только после этого помечает фото как `ready`, а одобрение размещений сбрасывает до повторной модерации.
- `GET /api/media/:id` читает закрытый бакет через сервер; фото отдается публично только для **активного объявления с одобренным размещением**, либо самому владельцу.
- В публичных `GET /api/listings` и `GET /api/listings/:id` возвращается `photo_url` обложки, в `GET /api/me/listings` — обложка собственных объявлений.
- Промежуточные метаданные хранятся в PostgreSQL, миграция `004_listing_photos.sql`.

## Настройки
S3 API должен поддерживать подпись AWS SigV4, HEAD, PUT, GET и Range. Например, совместимый закрытый бакет:

```dotenv
S3_ENDPOINT=https://storage.example.org
S3_REGION=ru-1
S3_BUCKET=yorvi-private
S3_ACCESS_KEY_ID=server-side-access-key
S3_SECRET_ACCESS_KEY=server-side-secret-key
```

`S3_ENDPOINT` должен быть **доступен из браузера** по HTTPS: именно на этот адрес браузер выполнит PUT по подписанной ссылке. Для разработки с локальным MinIO используются отдельные локальные переменные и бакет.

**CORS бакета**: разрешить только origin сайта YORI, метод `PUT` и заголовок `Content-Type` (проверьте реальные заголовки SigV4), допустимый объём не более 5 МБ. Бакет не должен быть публичным; для скачивания используйте `/api/media/:id`.

**Секреты хранятся только на сервере.** Не задавайте `VITE_S3_*` и не публикуйте `.env`.

## HTTP-контракт

1. `POST /api/media/uploads` с телом `{"listingId":"uuid","contentType":"image/jpeg","size":123456}` и подтверждённой сессией.
2. В ответе `mediaId`, `uploadUrl` и необходимые `headers`.
3. `PUT uploadUrl` с файлами (не multipart) и указанным `Content-Type`.
4. `POST /api/media/:mediaId/confirm`. В ответе `photoUrl`.
5. Повторно загруженный товар требует модерации.

## Ограничения текущего этапа
- **Настоящий S3 не подключён**: нужны endpoint, бакет, ключи доступа и CORS. Без них API корректно возвращает 503, загрузить фотографию нельзя.
- Подпись и формат проверяются, но пока **нет полного декодирования и нормализации изображений**, антивируса, EXIF-очистки, генерации миниатюр, явного удаления изображений, квот пользователя, очистки просроченных pending-объектов и теста реальной S3-загрузки.
- Публичный каталог уже читает PostgreSQL. В production **не должны появляться фальшивые демо-товары**, если база пустая или недоступна; в Vite dev старые демоданные остаются для UI-разработки.
- После подключения бакета требуется тест загрузки через мобильный MAX WebView и проверка поддерживаемых CORS-заголовков.
