# YORVI — сценарии записи объявлений (alpha)

Новые маршруты реализованы на Fastify и PostgreSQL. Это **локальный разработческий API**; настоящей авторизации MAX пока нет, поэтому все операции записи по умолчанию возвращают `401`.

## Как включить локальный тестовый режим

Только на отдельной локальной тестовой БД установите:
```
ALLOW_DEMO_AUTH=true
NODE_ENV=development
```
Для POST/PATCH запросов передайте `x-demo-user-id` с UUID **существующего** пользователя из тестовых данных. Никогда не выставляйте `ALLOW_DEMO_AUTH=true` на публичном сервере.

## Маршруты

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/listings` | Создание черновика, идемпотентное по requestKey |
| `GET /api/me/listings` | Список своих объявлений с размещениями |
| `POST /api/listings/:id/submit` | Отправка в 1–10 кругов, одна транзакция |
| `GET /api/moderation/queue?communityId=...` | Заявки доступные модератору конкретного круга |
| `POST /api/placements/:id/moderate` | Одобрение или отклонение с записью аудита |
| `PATCH /api/listings/:id` | Изменение полей владельцем, сброс одобрений для повторной проверки |
| `POST /api/listings/:id/sold` | Атомарная отметка «Продано» |
| `GET /api/listings` | Публичная выдача только активных и одобренных объявлений |

### Пример тела запроса на отправку объявления
```json
{"communityIds":["22222222-2222-4222-8222-222222222222"]}
```

### Правила
- Неизвестный продавцу товар возвращает 404; нельзя редактировать проданный товар.
- Отправка в одну и ту же витрину повторно не создаёт дубль. Отклонённое размещение можно отправить на проверку повторно.
- Одобрение действует только в конкретном круге.
- Изменение названия, цены и описания сбрасывает имеющееся одобрение и требует новой проверки.
- Продавец может продать активный или зарезервированный лот; после этого товар скрывается во всех публичных выдачах.
- Модератор не может одобрить собственный круг без соответствующей роли или полномочия владельца.
- Решения записываются в `moderation_actions`. Таблица добавлена миграцией `002_moderation_audit.sql`.

## Проверка

GitHub Actions выполняет `npm test`, `npm run build`, подготовку PostgreSQL, чтение каталога и отдельный интеграционный тест создания → размещения → одобрения → редактирования → повторной модерации → продажи.

До реального запуска: добавить проверку подписанных данных MAX на сервере, журнал действий и rate limiting для мутаций, отдельные роли, авторизацию хранения фото, обработку ошибок и продакшен-тесты.
