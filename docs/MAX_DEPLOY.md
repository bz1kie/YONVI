## 1. Развернуть HTTPS

Для существующего React/Fastify/PostgreSQL добавлен готовый шаблон Docker Compose + Caddy: [развёртывание LAVOSE на VPS](PRODUCTION_VPS.md). Домен и VPS пока не настроены.

Разместить frontend и backend под **одним HTTPS origin** (например, `https://<ваш-домен>`):
- `/` → собранный `apps/web/dist` (Vite/React);
- `/api/*` → Fastify (локально порт `3001`);
- `/health` → Fastify для технической проверки.

Важно: прокси `/api` в `apps/web/vite.config.ts` работает **только локально** во время разработки. В production нужен реальный HTTPS reverse proxy или эквивалентный маршрутизатор.

Не подключать Mini App к MAX, пока не развернуты и не проверены backend, PostgreSQL и SSL. Фотографии дополнительно требуют закрытого S3-совместимого хранилища с HTTPS и правильно настроенным CORS.

## 2. Настроить секрет только на API-сервере

В настройках окружения сервера/контейнера API задать:

```dotenv
NODE_ENV=production
ALLOW_DEMO_AUTH=false
DATABASE_URL=postgresql://<user>:<password>@<host>:5432/<database>
WEB_ORIGIN=https://<ваш-домен>
MAX_YONVI_TOKEN=<ваш-реальный-токен-MAX>
```

Приложение поддерживает либо `MAX_YONVI_TOKEN`, либо прежний `MAX_BOT_TOKEN`. Если заданы оба, приоритет у `MAX_BOT_TOKEN`. Удалите устаревшую переменную при миграции, чтобы случайно не использовать неправильного бота.

GitHub repository secret `MAX_YONVI_TOKEN` **не поступает автоматически на production-сервер**. Только явный deployment workflow/секретное хранилище хостинга может безопасно передать его. `.github/workflows/ci.yml` — тестовый workflow; `.github/workflows/render.yml` выполняет развёртывание и передаёт секрет в Render. Не нужно подключать боевой токен к тестам или pull_request CI.

Запрещено добавлять токен в репозиторий, `VITE_*` переменные, страницы, скриншоты и публичные логи. Не включайте `ALLOW_DEMO_AUTH=true` в публичном окружении.

## 3. Проверить API и вход

1. Открыть `https://<ваш-домен>/` и убедиться, что загружается каталог.
2. Проверить `GET https://<ваш-домен>/health`: ответ должен быть `{"ok":true,...}`.
3. Проверить `GET https://<ваш-домен>/api/auth/me` вне MAX: для гостя ожидается `401`.
4. Внутри MAX после реального открытия приложения компонент авторизации должен получить подписанный `initData`, отправить POST `/api/auth/max` и создать cookie-сессию. Без реального запуска в MAX этот шаг нельзя считать проверенным.
5. Проверить каталог, сохранение объявления, круги, обновление фотографии и права нескольких разных пользователей.

## 4. Привязать URL в MAX

По актуальной документации MAX:
1. Открыть [MAX для партнёров](https://business.max.ru/) → **Чат-боты**.
2. Выбрать бота **LAVOSE | Объявления** → **⋮ → Настройки**.
3. Вставить **реальный HTTPS URL** запущенного приложения.
4. Выбрать кнопку открытия **«Открыть»** и сохранить.

Требования MAX: HTTPS, валидный адрес длиной до 1024 символов. После сохранения в чате с ботом появится кнопка запуска Mini App.

Для внешнего открытия после привязки поддерживается формат `https://max.ru/<botName>?startapp`. Не публиковать его как рабочий, пока URL Mini App не привязан и не проверен.

## Связь с каналом MAX
Канал владельца: https://max.ru/se14029050_biz. Публичный channelId 81082274981279 подтверждается запросом API перед записью. MAX_CHANNEL_ID и MAX_CHANNEL_URL задаёт deployment script.
При запуске сервер проверяет членство и права бота, определяет владельца канала через MAX и сопоставляет его с подтверждённой учётной записью. При единственном круге владельца связывает его; иначе создаёт отдельный круг канала. Повторная проверка доступна владельцу в профиле → «Канал MAX».
Связь хранится в max_channel_links (миграция 005). Проверка не отправляет посты, не меняет подписки webhook и не читает личные сообщения. Одобренные активные объявления автоматически отправляются в привязанный канал (текст, цена, город и ссылка) каждые 30 секунд, включая уже одобренные до развёртывания. Состояние хранится в max_channel_posts (миграция 006), уникальное по размещению. Повторный запуск не дублирует отправленные посты. При сетевой неопределённости автоматический повтор отключён; проверьте канал вручную. Фотографии, синхронизация правок/продажи и личные уведомления пока не реализованы.

## Связь с продавцом
В профиле → «Связь с покупателями» продавец добровольно сохраняет публичную ссылку на личный профиль MAX формата https://max.ru/u/… . Она доступна в публичных карточках его одобренных объявлений. ID пользователя не публикуется и не используется для выдумывания ссылки. Пустое поле удаляет контакт. Изменение разрешено только текущему пользователю по защищённой сессии. Ссылка задаётся продавцом, принадлежность профиля автоматически не подтверждается.

## Переписка по объявлениям
Миграция 009 создаёт conversations, conversation_messages и conversation_notifications. Участники определяются сервером: покупатель из защищённой сессии, продавец из объявления. Посторонние не могут читать и отправлять сообщения. Диалог создаётся только для активного объявления, одобренного в публичном круге. Повторная отправка с тем же requestKey не дублируется. Профиль → «Сообщения покупателей и продавцов» открывает входящие; в карточке доступна кнопка «Написать продавцу». Ручная ссылка больше не требуется. Отображаются последние 100 сообщений, обновление каждые 5 секунд при открытом диалоге.
Уведомления MAX отключены по умолчанию. Продавец/покупатель включает их в профиле и запускает бота. Текст уведомления не содержит переписку; кнопка запускает мини-приложение с параметром conversation_UUID. При недоступности бота или неопределённой доставке сообщения остаются доступны внутри Лавось, уведомление автоматически не повторяется. История хранится в PostgreSQL; фотографии, вложения, блокировка собеседника, жалобы и статусы прочтения пока не реализованы.

## Мобильная компоновка
Основные разделы: Поиск, Избранное, Объявления, Сообщения, Профиль. Каталог открывается первым, категории листаются горизонтально, товары показаны в две колонки. Поиск закреплён сверху; цена, категория, город, сортировка и сообщество фильтруют реальные данные. Настройки уведомлений и управление каналом вынесены в профиль; права управления определяются сервером через /api/me/managed-communities. Объявления разделены по статусам. Текст нового черновика сохраняется на устройстве под ключом пользователя; фотографии и состояние редактирования не сохраняются локально. Сообщения отображаются отдельным экраном и доступны из нижнего меню.
